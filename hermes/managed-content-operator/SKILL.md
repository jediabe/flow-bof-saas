# Managed Content Operator Skill

Use this skill when a human asks Hermes to turn an approved product into a privately persisted, QA-approved, ready-to-post MP4 through the managed ContentRun path. Hermes decides what to ask for and which approved SaaS MCP tool to call next; the SaaS decides whether the operation is permitted.

This skill does not implement provider code, edit SaaS lifecycle state, repair media, post to TikTok, or bypass the managed run surface. For managed runs, never raw Google Flow, never database writes, and never lifecycle invention from chat history.

## When to Use

- The user asks for a ready-to-post TikTok MP4 from an approved product using Style1 or Style2.
- The run must use managed ContentRun tools and stop at a downloadable private final MP4 for manual upload.
- The user needs an operator transcript, handoff, or repeatable runbook for Style1 store discovery or Style2 MOF avatar variants.

Do not use for: Style3, platform uploading, billing/onboarding/analytics, raw provider experiments, or any unmanaged Flow workflow.

## Prerequisites

- Product identity is unambiguous and `content_get_product` returns `reviewStatus: approved`. If the product is missing, rejected, or not approved, stop before spend.
- Style is explicit or safely inferable as Style1 or Style2. Support only Style1 and Style2; Style2 variants are exactly `handheld`, `large_countertop`, and `worn`.
- Clarify genuine style, product, or compiler input ambiguity before the run. For Style2, W4A compiler input includes registered character reference, product type/form/count, copy, product/garment reference IDs when applicable, optional seed/recent hashes, and variant.
- Never inject model unless the human explicitly selected an allowlisted model accepted by the SaaS. Otherwise let the SaaS frozen defaults apply.
- Keep `references/tool-contracts.md` loaded beside this file before operating.

## Approved Tool Surface

Only these managed MCP tools are valid for this skill:

1. `content_get_product`
2. `content_create_run`
3. `content_generate_image`
4. `content_generate_video`
5. `content_run_qa`
6. `content_run_final_output`
7. `content_get_run`

No other content generation, provider, platform upload, database, or lifecycle tool is part of the managed operator contract.

## Idempotency Keys

Use stable keys so replays resume rather than duplicate spend:

- Objective idempotency key: hash the exact W4A-accepted `content_create_run` input after removing only the `idempotencyKey` field. That document contains exactly `productId`, `style`, optional human-selected `videoModel`, and singular `compilerInput`; it does not contain top-level `variant`, `objective`, or `compilerInputs` because W4A rejects those fields. Normalize strings with Unicode NFC, trim only leading/trailing whitespace, preserve human-approved casing inside values, omit undefined fields, use sorted keys recursively, serialize as canonical JSON with no insignificant whitespace, then compute SHA-256 over the UTF-8 bytes and encode the digest as lowercase hex. Format: `managed:<productId>:<style>:<compilerInput.variant>:objective:sha256-<64 lowercase hex chars>`.
- Slot idempotency key: stable per run and manifest slot. Format: `managed:<contentRunId>:<slot>:generate`. The slot appears in the key and SaaS projection, not in the W4A generation command arguments.
- Final idempotency key: one run-stable final-output root for all final-output calls. Format: `managed:<contentRunId>:final-output`. W4A derives voiceover, assembly, and final-QA subkeys internally from this root; Hermes must replay the same root for each projected final phase.

Do not add timestamps, random suffixes, attempt counters, chat message IDs, model names, operation IDs, or final phase names to idempotency keys. WAIT replays use the same W4A-accepted command and the same key.

## Procedure

1. Fetch the product with `content_get_product`. Continue only when the returned product has `id` matching the selected product and `reviewStatus: approved`; otherwise stop and explain what is missing.
2. Resolve style and compiler input. Clarify only genuine ambiguity; do not ask about defaults the SaaS manifest owns.
3. Create or resume the run with `content_create_run`, passing `productId`, `style`, singular schema-valid `compilerInput`, objective idempotency key, and only human-approved optional `videoModel`. Do not pass top-level `objective`, `variant`, or `compilerInputs` unless W4A changes its schema.
4. Read the returned `nextAction` or nested `run.requiredNextAction` and follow it exactly. Do not skip ahead based on chat history or memory.
5. For `GENERATE_IMAGE`, call `content_generate_image` with only `contentRunId` and the slot idempotency key. The SaaS reads the slot from persisted `requiredNextAction`.
6. For `GENERATE_VIDEO`, call `content_generate_video` with only `contentRunId`, the slot idempotency key, and optional bounded `creativeDirection` where the manifest allows it. Do not pass `slot` or `sourceAssetId`; the SaaS reads those from persisted `requiredNextAction`.
7. For `RUN_QA`, call `content_run_qa` with only `contentRunId`. Then call `content_get_run` and use its nested `run.requiredNextAction` as sequencing authority before any next generation or final-output call. There is no QA skip, override, or repair path.
8. For `GENERATE_VOICEOVER`, `ASSEMBLE_FINAL`, or `RUN_FINAL_QA`, call `content_run_final_output` with only `contentRunId` and the run-stable final-output idempotency root. Do not pass `phase` or `finalVideoId`; W4A reads the phase from persisted `requiredNextAction`.
9. For `WAIT_FOR_OPERATION`, repeat the same W4A-accepted command with the same idempotency key. Approved W4A supports same-key video-generation WAIT replay and final-output WAIT polling; do not invent image WAIT replay because synchronous image generation has no safe in-flight replay path.
10. For `HUMAN_REVIEW`, stop. Report the SaaS reason and do not retry, repair, or override QA.
11. For `FAILED`, stop. Report the SaaS terminal reason; the existing ContentRun is terminal and must never be resumed, retried, or used for further spend. If a human later requests a fresh attempt and architecture permits a distinct ContentRun, require genuinely changed canonical W4A create data; unchanged compiler input deterministically maps to the same objective key and must not be spent against a terminal run.
12. For `COMPLETE`, call `content_get_run` and verify READY only after `content_get_run` confirms final MP4 persisted and final QA approved. If those final invariants are not visible, continue from the returned `run.requiredNextAction` or stop with the mismatch.
